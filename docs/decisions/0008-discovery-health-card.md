# 0008 — Discovery health: broken-discovery evidence card

- **Date:** 2026-10-01
- **Status:** ACCEPTED — explicit human design-authority change (2026-10-01)
- **Phase:** post-Phase-11 product hardening (discovery reliability follow-up)

## Issue

On hosts where the shared ADB server's mDNS browse silently returns empty complete lists
(`research/2026-09-19-host-mdns-empty-while-tcp-works.md`), Adb View shows zero offers and zero
errors: the ADB server reports itself healthy, the product correctly maps empty complete-lists to
zero offers, and the user sees nothing — no offers, no explanation, no way to tell a quiet network
from a broken one. Field diagnosis on the affected host identified two correlated environmental
causes (virtual network adapters; other applications holding the discovery port) and established
that unicast pair/connect continues to work while browse is broken.

The product's mission is *observe → explain*. Today it observes correctly but cannot explain this
failure class. The existing `Wireless discovery unavailable` warning (ENGINEERING §11 rows 8/9)
covers tracker *failure*, not empty-but-healthy browse, and DESIGN.md has no surface for it.

## Decision

A new local informational surface, the **DiscoveryHealthCard**, appears when wireless discovery is
provably not working. It is placed **after pairing cards and before subsystem warnings** in the
flyout content order.

### Appearance trigger (all must hold; event-driven, no timers)

1. At least one connected device reports the **Wi-Fi** transport (a Wi-Fi-connected device must be
   announcing itself — its absence from discovery is the anomaly).
2. The mDNS service stream currently reports **zero services** (any kind).
3. The ADB server is healthy and reports wireless discovery enabled
   (not the existing tracker-failure / mdns-disabled paths, which keep their existing surfaces).

When a connected Wi-Fi device disappears or any service appears, the card clears immediately.
There is **no grace delay**: the trigger combination itself is already the anomaly signal, and
churn (wireless-debugging off/on) self-clears because the device leaves the tracker first.

### Silence rule

A healthy-but-quiet network (no Wi-Fi device connected, zero services, ADB healthy) shows
**nothing**. The card never appears without the trigger above. (Explicit design-authority choice,
2026-10-01.)

### Content and copy

Title and body are frozen; evidence lines are generated by `Vocabulary` from structured diagnosis
(no jargon: no "UDP", no "mDNS", no port numbers, no adapter driver names beyond the product names
the user recognizes):

| Element | Copy |
|---|---|
| Title | `Wireless discovery isn't working` |
| Body | `{device} is connected over Wi-Fi, but ADB isn't receiving device announcements on this network.` (first connected Wi-Fi device's display name) |
| Evidence: announcements measured | `N device announcements are visible on this network.` — confirms the ADB server is dropping what the network delivers |
| Evidence: probe inconclusive | `ADB View couldn't measure the network just now.` |
| Evidence: discovery port held | `Microsoft Edge is using the discovery port.` / `Microsoft Edge and 2 other apps are using the discovery port.` (Adb View's own process and the ADB server itself are never named) |
| Evidence: virtual adapters | `Virtual network adapters are active (Tailscale, Hyper-V).` (up to two product names, else no names) |
| Action | `Check again` — re-runs the one-shot measurement; disabled while it runs |

Evidence lines appear only when the corresponding measurement produced a finding; the card may
show title + body + `Check again` alone. The visual treatment reuses the existing local-warning
card language (informational, restrained) — no new visual language.

### Measurement behaviour

The one-shot reference probe (RFC 6762 §6.7 legacy-unicast query from an ephemeral port —
`research/2026-10-01-discovery-diagnostics-evidence.md`) runs **only** when the flyout is opened
while the card is visible, and when `Check again` is pressed. It is never scheduled (R-05).
Port-ownership and adapter enumeration run on the same occasions and on trigger transitions.

### Notification

None in the base change (Step 1). The Step 2 amendment below adds the episode balloon.

## Amendment (2026-10-01) — repair actions, verify-and-report, episode balloon

Human-approved follow-up to the base decision. The evidence card gains **repair actions**,
**a momentary result line**, and **one balloon per broken episode**. This amendment revises
**R-14** for exactly one action: a *user-initiated* ADB server restart from the card's approval
button (`adb kill-server` spawned as a client process — never `host:kill`, never scheduled,
never automatic). Recovery after the kill remains fully owned by the existing supervisor and
tracker lifecycles. The source-boundary token list is updated to allow `kill-server` in
`AdbProcessRunner.cs` only; every other ADB-core file stays forbidden, and the FakeAdbServer
socket-level kill assertion remains strict (the sanctioned kill never goes through the socket).

### Actions (closed set, approval-gated, evidence-gated)

| Id | Command surface | Elevation | Offered when | Undo |
|---|---|---|---|---|
| `restart-adb` | `adb kill-server` (spawned client) | none | card visible | not needed (supervisor restarts) |
| `stop-service:Tailscale` | `sc.exe stop Tailscale` | UAC prompt per run | Tailscale service present and running | `start-service:Tailscale` |
| `disable-adapter:{name}` | `netsh interface set interface name={name} admin=disable` | UAC prompt per run | a virtual adapter was measured | `enable-adapter:{name}` |

- Admin commands are fixed executables with `ArgumentList`-built arguments; adapter names are
  charset-validated before use. No shell, no interpolation of user input (R-13).
- Declining the UAC prompt is a logged no-op shown as "not run — approval was declined".
- Completed admin actions unlock the symmetrical undo action on the same card.
- After every completed action the app re-measures automatically (event-driven: for
  `restart-adb`, after the next server `Up` generation and the first complete mDNS frame; for
  admin actions, immediately after the process exits). No sleeps, no timers (R-05).

### Result line (momentary)

When the post-action measurement still finds discovery broken, the card shows
`Still not working after this action.` once; the line clears when the evidence next changes or
the card clears. Declined/failed actions show their own momentary line. Restoration clears the
card entirely (the trigger is gone) — never a persistent success badge.

### Episode balloon

`DiscoveryBroken` notification intent: edge-triggered when the card appears (1.5 s hold,
cancelled if the card clears during the hold), latched to one per episode (cleared when the card
clears, so a later episode notifies again), title/body identical to the card copy (§32
same-terminology). Subject to the existing master switch, burst accounting, and startup/resume
suppression.

### Contract changes

- `DiscoveryHealthView` gains `Repairs` (id, label, kind, per-action state) and a momentary
  `ResultLine`; `Vocabulary` owns every new string (R-15 — no command names, no "sc.exe"/"netsh",
  no "UAC" on any surface).
- New bridge action `discoveryRepair {id}`; the frontend sends only opaque ids — the
  backend resolves them against its own catalog.
- Boundary token list carve-out as described above (tested).

### Rejected (amendment)

- Restarting ADB automatically or on a schedule — citizenship/R-05.
- Offering repairs for arbitrary services/adapters beyond the measured evidence — the closed set
  exists to keep every command line fixed and auditable.
- Persistent undo entries — undo exists only while its completed action's effect is the live
  state (service stopped / adapter disabled this session).

## Contract changes

- `AppSnapshot` gains a nullable `DiscoveryHealth` view (structured, wording rendered in
  `Vocabulary`); the existing `SubsystemWarningView` contract is unchanged.
- New frontend component `DiscoveryHealthCard` in the §40 component list; rendered from data like
  every other card (no alternate markup families).
- `DESIGN.md` §18 gains the surface description; §40 gains the component name.

## Rejected alternatives

- Extending `SubsystemWarningView` with evidence/action fields — overloads a frozen contract and
  conflates two distinct failure classes (tracker failure vs empty-but-healthy browse).
- Global (red) health surface — §17: global health must not overwrite truthful device states; a
  connected Wi-Fi device is not a global failure.
- Showing an informational card on healthy-quiet networks — noise; rejected by design authority.
- Automatic probes on a schedule — R-05; measurement is event/user-triggered only.
- Naming the apps' protocols or port numbers on the card — R-15 vocabulary discipline.

## Testing

- `DiscoveryHealthView` trigger truth table in the reducer: Wi-Fi-connected × services-empty ×
  server-healthy combinations; USB-only devices never trigger; churn clears the card.
- Diagnostics collectors behind native seams (fake UDP tables / adapter lists; exited-PID rows
  counted per R-08; `adb.exe` and own-PID excluded from the port-held line).
- DNS probe parser against a captured legacy-unicast response fixture.
- FakeAdbServer scenario: trigger fires with a connected Wi-Fi device + empty mdns stream; card
  clears when any service returns.
- Vitest + visual baseline for `DiscoveryHealthCard` (dark/light, 100–200 % scale).
- Live matrix rows: 5353 binder list matches `netstat -ano`; probe measures announcements while
  `adb mdns services` is empty on the affected host (the acceptance).
